# 엔딩 갈래 · 질문 고정 · 취조서 문서 · main 검사 장치 — 설계 (2026-11-25)

사용자 요청(11/24 22:30): "제작자 모드에서도 질문 순서는 못 바꾸게", "범인과 경찰 둘 다 정답을 맞출 경우,
둘 중 하나만 맞출 경우", "취조서는 룰북과 카드 탭 업데이트", "메인이 기준으로 다들 따를 수 있도록 시스템".
결정: 엔딩은 A안("그러자"), 검사 장치는 A안("첫번째가 좋다").

## 왜

- 3막의 두 마지막 질문이 결말과 이어지지 않았다. 범인의 질문은 자수서를 여는 데만 쓰이고,
  형사의 질문은 판결로 넘어가는 문일 뿐이었다. 둘을 누가 맞혔는지가 이야기의 갈래가 되어야 한다.
- 제작자 모드의 "JSON 적용"이 막의 질문까지 통째로 바꿀 수 있어서, 자수서 잠금이 다른 질문에 걸리거나 영영 안 풀릴 수 있다.
- 룰북·카드 탭은 옛 "취조서 세 칸"과 엔딩 6장을 설명한다. 티비는 취조서 한 칸 + 자수서 한 칸, 엔딩 9장이다.
- 여러 세션이 `main`을 같이 고치는데, 규칙(CLAUDE.md)을 어겨도 잡아 주는 것이 없다. 문서끼리 카드 수·규칙 문구가 계속 어긋났다.

## 1. 엔딩 갈래 (사용자 결정)

3막의 두 질문 — 형사: "피의자가 피 묻은 쿠키를 처음 받아먹은 곳은?"(다리) /
범인: "그녀는 왜 쿠키를 먹을까?"(피를 좋아하니까) — 을 누가 맞혔는지로 갈래가 정해진다.

| | 형사가 맞힘 | 형사가 못 맞힘 |
|---|---|---|
| **범인이 맞힘** | 고른 엔딩 + **히든 엔딩 「그녀의 이야기」** | **범인의 자수** — 자수서 S1·S2를 쓸 수 있다 → 엔딩 1·2·6·7·8·9. 안 쓰는 것도 허용("쓰지 못했다" → 3·4·5) |
| **범인이 못 맞힘** | **범인은 연쇄 살인마** — 자수서 못 씀 → 엔딩 3·4·5 | 진실 미도달 → 엔딩 4 |

- "범인의 자수"는 "자수할 수 있다"는 뜻이다 — 자수서 세 칸이 모두 열려 있고, 범인이 안 쓰면 3·4·5로 간다 (사용자: "안쓰는 것도 허용").
- 엔딩 9장(취조서 3 × 자수서 3, `VGRID`)은 그대로 둔다. 갈래는 자수서에 무엇을 쓸 수 있는지를 정할 뿐이다.
- "둘 다 못 맞힘"이면 취조서 선택과 상관없이 엔딩 4(「머랭」). 취조서 칸은 그대로 적게 하되(점수·분위기용)
  자수서는 "쓰지 못했다"만 열리고, 티비는 「머랭」을 부른다. *(제 결정)*
- "둘 다 맞힘"이면 자수서 세 칸이 모두 열린다(9장 중 어느 것이든).
- "둘 다 맞힘"이면 9장 중 고른 엔딩을 읽은 뒤 히든 엔딩 카드를 하나 더 뒤집는다.
  히든 엔딩 카드의 쿠키 이름은 「마들렌」(제 제안 — 바꿔도 된다), 뒷면 지시는 "엔딩 책자의 「그녀의 이야기」를 읽는다".
- 히든 엔딩 카드는 티비 `endings` 에 `E10`(「마들렌」, `"hidden":true`)으로 넣는다. 두 질문을 다 맞혔을 때만 티비가
  고른 엔딩 다음에 "그리고 — 「마들렌」을 뒤집는다"를 부른다. `VGRID` 에는 넣지 않는다. *(제 결정)*
- 「그녀의 이야기」는 이제 히든 엔딩에서만 읽는다. 엔딩 책자 설명·룰북·기획서 9절을 그렇게 고친다.
- 카드 수 +1: 지금 30장 → 31장 (63×88mm 26장 · A6 5장).

### 판결로 가는 문

지금 티비는 형사의 질문을 맞혀야만 4막(판결)으로 간다. 그러면 "범인만 맞힘"과 "둘 다 못 맞힘"에 갈 길이 없다.

- 3막 "4 기억" 채널에 **「시간이 끝났다 — 판결로 간다」** 버튼을 둔다. 3막에서만 보인다.
  누르면 형사의 질문을 못 맞힌 채로 4막에 들어간다. (종이 타이머 45분이 끝났을 때 누르는 버튼)
- 버튼은 두 번 눌러야 한다(첫 번째: "정말 끝났나? 한 번 더 누르면 판결로"). 넘어가면 되돌릴 수 없다 —
  종이 타이머가 끝난 것과 같다. 4막에 들어간 뒤에는 형사의 질문은 닫힌다. *(제 결정)*
- 형사의 질문을 맞히면 지금처럼 바로 4막.
- 범인의 질문은 지금처럼 판결이 끝날 때까지 답할 수 있다.
- 판결 화면 맨 위에 지금 갈래를 한 줄로 띄운다 ("범인의 자수 — 자수서를 쓸 수 있다" 등). 갈래가 바뀌면 그 줄도 바뀐다.
- 엔딩이 불린 뒤 범인이 질문을 맞히면, 갈래가 바뀌었다고 알리고 "처음부터 다시 적는다"를 권한다.
  (자동으로 엔딩을 바꾸지는 않는다)

## 2. 막의 질문 고정

- 막의 질문(`memory`)과 엔딩 목록(`endings`)은 **언제나 `DEFAULT_DATA`의 것**을 쓴다. 저장된 설계·제작자 모드 JSON·상대 폰 설계에 있어도 무시한다(`migrate()`에서 덮어쓴다).
- 제작자 모드 "적용"은 `memory`·`endings`가 기본값과 다르면 그 부분을 버리고 "막의 질문과 엔딩은 저장소 설계로만 바꾼다"고 알린다. 카드(사진·지점·문구·코드)는 지금처럼 고칠 수 있다.
- 제작자 모드 안내 문구에서 "기억 질문은 JSON에서 고친다"는 말을 뺀다.
- 자수서 잠금(`confessOpen`)과 갈래 계산은 "3막의 첫 번째 optional 질문"이 아니라 **질문에 붙인 이름표**로 찾는다:
  범인의 마지막 질문에 `"key":"herReason"`, 형사의 마지막 질문에 `"key":"bridge"`. 역할도 `m.role`로 읽는다.

## 3. 취조서 — 룰북·카드 탭

- 룰북 1절 구성물: 엔딩 카드 9 + 히든 1, 엔딩 책자 설명("그녀의 이야기는 히든 엔딩에서만").
- 룰북 7절을 티비 판결 화면 그대로 다시 쓴다: 취조서 한 칸(전부 피의자에게 / 손을 가른다 / 동생의 이름), 자수서 한 칸(S1 / S2 / 쓰지 못했다), 「시간이 끝났다」 버튼, 갈래 넷(스포일러 없이 — "마지막 두 질문을 누가 맞혔는지에 따라 쓸 수 있는 서류가 달라진다" 수준). 갈래 표의 상세는 정답 봉투·기획서에.
- 카드 탭: 옛 "취조서 세 칸" 표, "엔딩 카드 6장" 인쇄면·초안 표, "선택 카드 2장" 표를 지금 규칙(엔딩 9 + 히든 1, 3×3 표, 갈래)으로 바꾼다. 기획서 10절의 엔딩 표가 원본이다.
- 테스트 코드 탭: G3 행의 "형사: 비밀 ③을 읽는다"는 지금 티비대로(일기장은 K6 서랍 → 비밀 ③) 고친다.

## 4. main 검사 장치 (사용자 결정 A)

**`python3 tools/check.py` 하나로 모두 돈다.** 통과해야 푸시한다.

1. `tools/build.py` 를 돌린 뒤 `tv/index.html`·`docs/tv.html` 이 커밋된 것과 같은지 (안 같으면 "build 안 돌리고 커밋했다").
2. `tools/tvtest.py`, `tools/docstest.py` (둘 다 크롬이 없으면 Playwright chromium).
3. `tools/consistency.py` — 문서끼리 어긋남:
   - 금지 문구가 `text/`·`docs/index.html`·`tv/source.html` 에 없다: "이름을 들었을 때만", "4막 미도달", "발인 날 사라진 사람", "엔딩 카드 6", "취조서 세 칸" 같은 옛 규칙 (목록은 파일 맨 위에 두고 늘려 간다).
   - 카드 총수: 티비 설계(현장 카드 + 엔딩 + 특수) + 선택 카드 2 가 `text/기획서.md` 의 "카드는 모두 N장", 문서 모음 소개서·룰북 구성물 표와 같다.
   - 엔딩 수: 티비 `endings` 길이 = 기획서 9절 "엔딩 카드" 수.
   - 설계 버전: `tv/source.html` 의 `DEFAULT_DATA` 가 비교 기준과 달라졌는데 `version` 이 안 올랐으면 FAIL.
     비교 기준은 푸시 전(훅)에는 `origin/main`, GitHub에서는 푸시 직전 커밋(`github.event.before`). *(제 결정)*
   - 막의 질문 순서·이름표(`herReason`, `bridge`)가 있다.
4. 결과를 한 줄씩 OK/FAIL, 마지막에 통과 수.

**푸시 전에 자동으로:** `tools/install-hooks.sh` 가 `.git/hooks/pre-push` 를 깐다 — `check.py` 가 실패하면 푸시를 멈춘다.
CLAUDE.md 1절에 "저장소를 받으면 `bash tools/install-hooks.sh` 를 한 번 돌린다"를 넣는다.

**GitHub에서도:** `.github/workflows/check.yml` — `main` 에 푸시될 때마다 같은 `check.py` 를 돌린다.
깨지면 저장소에 빨간 표시가 뜬다. (GitHub 토큰에 workflow 권한이 없어 이 파일 푸시가 거절되면,
파일만 저장소에 두고 사용자에게 GitHub 웹에서 한 번 켜 달라고 한다.)

**CLAUDE.md:** 2절에 "푸시 전 `check.py` 통과", 7절 요약을 지금 규칙(일기장은 형사 비밀 ③, 엔딩 갈래, 질문 고정)으로 고친다.

## 하지 않을 것

- 정답 봉투(티비 없이 종이로 하는 판)의 원본은 저장소에 없다. 이번에는 만들지 않는다 — 티비 오프라인 파일이 있다. *(제 결정)*

- 점수표는 보류 그대로.
- 엔딩 9장의 조합(`VGRID`)과 각 엔딩 문장은 바꾸지 않는다. (엔딩 3의 "그 애 이름이 뭐였죠?"가 새 규칙과 조금 어긋나는 것은 점수표와 함께 따로 본다.)
- 규칙 데이터 하나(`game.json`)로 모으기(B안)는 하지 않는다.
- Claude 문서(기획서·핸드아웃)를 자동으로 내보내는 장치는 만들지 않는다 — 고친 세션이 손으로 내보낸다.
